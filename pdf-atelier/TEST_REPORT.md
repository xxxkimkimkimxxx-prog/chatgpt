# PDF Atelier 端末内版 検証報告

実施日：2026-09-22

| 区分 | 結果 | 内容 |
| --- | --- | --- |
| 本番Webビルド | 合格 | PDF.js Worker、Noto Sans JP、OCR資材を自己ホスト用成果物へ格納 |
| Python回帰＋保護 | 合格 65件 | 旧機能回帰、API本文を読む前の拒否、CSP、コンテナからPython文書エンジン除外 |
| API停止 | 合格 2件 | 開発・プレビュー環境で全文書APIを403拒否 |
| 静的配信 | 合格 4件 | 静的資材、SPA、API誤配信防止、Sites構成 |
| 端末内エンジン | 合格 6件 | 回転、複製、削除、並べ替え、結合、選択ページ抽出、PNG画像配置、マーカー・囲み枠、拒否系、DOCX/XLSX構造、送信コード検査 |
| ブラウザー操作 | 未確認 | 専用ブラウザー検証コマンドが環境に存在しない |
| iPhone操作 | 未確認 | 実機でのOCR、ダウンロード、メモリー上限確認が必要 |
| 公開版 | 未反映・未確認 | 機密文書で利用不可 |

## 確認済みの保護

- アクティブ画面は旧サーバー型 `App.jsx` を読み込まない。
- アクティブな編集コードに `/api/` へのPDF送信、XHR、Beacon、WebSocketがない。
- Render/Vercel APIは本文未送信の状態でも直ちに拒否応答するため、サーバー処理を開始しない。
- コンテナは `engine.py` と `engine_cli.py` をコピーしない。
- CSPは外部オリジンを許可せず、同一配信元のコード、フォント、Worker、OCR資材だけを許可する。
- 文字中心・見た目優先のDOCX/XLSXを生成し、python-docx／openpyxlで再度開ける。見た目優先Excelではページ画像の存在も確認した。
- 1ピクセルPNGをPDFへ端末内で埋め込み、出力PDFを再読込してページ構造が保たれることを確認した。

## 残る重要な確認

- 実ブラウザーでPDFを開き、各操作後の表示と保存PDFを目視比較する。
- 日本語文字追加の位置、折返し、切れ、画質を複数ページサイズで確認する。
- OCR Workerが日本語・英語データを外部アクセスなしで読み込むことをNetwork記録で確認する。
- iPhone Safariで5ページOCR時のメモリー、発熱、途中キャンセル、ファイル保存を確認する。
- 生成DOCXをWord、XLSXをExcelで実際に開き、警告なく表示できることを確認する。
- 公開後に旧JavaScriptがキャッシュから使われず、API拒否ヘッダーと最新版ハッシュが一致することを確認する。

## 判定

基本処理のソース実装と自動テストは合格です。しかしブラウザー・iPhone・公開版の実動確認が残るため、「機密文書対応の公開完成版」とは判定しません。
